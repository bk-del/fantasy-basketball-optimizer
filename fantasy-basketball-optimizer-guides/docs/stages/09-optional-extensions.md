# Stage 09 — Optional extensions (not automatically authorized)

Only begin when Stage 08 works and owner requests an extension. For each feature, write a small proposal with cost, data requirement, measurable success criterion, and rollback plan. Prioritize by tested uplift, not complexity.

Potential experiments:

1. Multiweek model-predictive control with variable transaction scarcity and playoff prioritization.
2. Opponent streaming and waiver-claim-risk priors, if Yahoo transaction history is available and enough evidence exists.
3. Adaptive roster/category punt and Pareto frontier display.
4. Smarter search: beam search, integer programming, sequential Monte Carlo candidate allocation.
5. Optional GPU/CUDA only after CPU profiling proves a repeated throughput bottleneck.
6. More advanced Bayesian role/change-point models if relevant observed features exist.
7. Dashboard, notification service or optional scheduling after CLI reliability.

Never add paid inference, scrape unofficial sources, or introduce non-Yahoo runtime data without explicit owner permission. Each experiment gets a benchmark or walk-forward test and is rejected if it fails to improve results.
